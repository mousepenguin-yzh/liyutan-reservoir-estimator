# 鯉魚潭水庫庫容推估系統

這是一套以 Streamlit 建置的鯉魚潭水庫逐日庫容情境推估工具，協助水庫營運與水源調配承辦人，把例行推估所需的日期、入流、出流、調度條件與成果整理在同一個工作流程中。

系統是依人工設定條件進行演算的決策輔助工具，不是即時水文預報模型，也不取代正式調度決策。

開發狀態見 [專案目前狀態](docs/PROJECT_STATUS.md)。

## 主要功能

- 建立 1～N 個可命名、複製、排序與比較的入流情境。
- 設定近期共用入流，後續再依不同氣候或專業判斷分流。
- 套用 Q5～Q95、水利署貼入值或人工調整值。
- 共用一套出流需求，並可加入指定日期的抗旱或臨時調度覆寫。
- 批次執行逐日庫容演算，比較期末庫容、最低庫容、溢流、農業減供與空庫天數。
- 查看庫容歷線、旬表、逐日明細並下載 CSV。
- 下載／載入工作批次 JSON，或在共享模式中從已驗證的正式版本建立新工作。
- 由受控流程建立年度基準版本及正式推估版本。

主要單位：流量使用 cms（立方公尺／秒），水量與庫容使用萬噸；`1 cms = 8.64 萬噸／日`。

## 一般工作流程

1. 設定展示期間、推估期間，以及推估起點前一日 24:00 的實際庫容。
2. 建立入流情境，填入近期共用入流與各情境後續入流。
3. 檢查年度基準出流，視需要調整旬需求或加入日期覆寫。
4. 執行全部情境，先看摘要，再查看單一情境的圖表、旬表與逐日結果。
5. 下載成果、加入工作階段比較；需要形成正式紀錄時，再依畫面完成預覽與明確確認。

任何必要輸入改變後，都應重新演算；不要把舊結果視為目前設定的有效結果。

## 正式資料與工作階段資料

| 類型 | 用途 | 保存方式 |
| --- | --- | --- |
| 年度基準資料 | 共用 Q 值、年度出流與水庫參數 | 由受控維護流程建立不可變版本，人工確認後才啟用 |
| 正式推估版本 | 保存某次推估的完整條件、結果、來源與備註 | 經預覽與再次確認後新增版本，不覆蓋舊版 |
| 工作階段資料 | 臨時上傳、試算、尚未正式保存的情境與結果 | 只屬目前 Streamlit 工作階段，關閉或重啟後可能消失 |
| JSON 設定檔 | 手動攜帶一批工作設定 | 可下載到另一台電腦再載入，但不會自動同步或自動恢復 |

執行推估、查看結果或加入比較區，都不等於正式保存。工作階段上傳也不會自動修改年度基準；請以畫面顯示的資料來源與版本為準。

## 啟動方式

目前需在 repository 目錄中啟動：

```bash
pip install -r requirements.txt
streamlit run app.py
```

若只需相容模式的內建資料，不要啟用 shared storage。正式公司環境的共享模式應由維護者設定；基本 PowerShell 形式如下：

```powershell
$env:LIYUTAN_ENABLE_SHARED_STORAGE = '1'
$env:LIYUTAN_SHARED_ROOT = '<由維護者提供的共享根目錄>'
streamlit run app.py
```

共享模式啟用後，路徑、權限或資料驗證失敗都會明確顯示，不會無提示改用舊快取或內建資料。年度資料寫入、正式推估寫入及 recovery 另有預設關閉的維護者功能開關；一般使用者不應自行開啟。

## 一般使用注意事項

- 先確認畫面顯示的年度資料版本、資料來源與共享儲存狀態。
- 未填入流不能用 0 或任意 Q 值代替；需由承辦人明確填入或套用。
- 同一批次的情境共用出流條件；若要比較不同出流或調度方案，請建立不同批次。
- 正式保存前，確認推估期間、選定情境、操作人、備註、年度版本及調整資料標記。
- 內建備援資料與工作階段上傳是非正式資料來源，不應被誤認為最新年度基準。
- 若共享資料異常、版本已變更或結果已過期，先依畫面指示重新載入、確認或演算，不要繞過警示。

## 目前限制

- 本模型是例行操作的簡化模型，未明確納入蒸發、滲漏與河道旅行時間等項目。
- 尚未提供一般使用者的一鍵桌面啟動與自動更新流程。
- 非正式工作不會自動跨瀏覽器、跨工作階段或跨電腦同步。
- 操作人名稱是人工填報，不代表已登入或已驗證身分。
- 真實 Windows／SMB、多電腦環境的目前驗收狀態請見 [專案目前狀態](docs/PROJECT_STATUS.md)。
