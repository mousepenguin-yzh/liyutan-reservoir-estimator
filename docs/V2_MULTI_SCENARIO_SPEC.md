# V2 多情境推估工作流程規格

狀態：第一階段已完成並驗收（2026-08-14）  
適用專案：鯉魚潭水庫庫容推估系統  
合併紀錄：[PR #3](https://github.com/mousepenguin-yzh/liyutan-reservoir-estimator/pull/3)  
本階段範圍：多情境輸入、共用出流、批次演算、步驟四與步驟五銜接  
本階段不包含：任何共用永久資料源、正式版本永久保存、跨裝置自動記憶、帳號／管理密碼、德基系統修改（Google Sheet 為當時曾評估的候選方向，現行第二階段決策見第 9 節）

## 0. 第一階段完成紀錄

- 已完成 1～N 個入流情境、共用 0 旬至全部推估旬、共用出流、批次演算及 JSON 設定交換。
- 步驟四以批次摘要搭配單一情境詳情呈現；步驟五可整批或個別加入，並保留跨批次比較。
- 人工驗收期間修正共用旬首次輸入、Q 值重新套用、摘要近零值與小數位顯示、步驟五顯示名稱，以及清空後重新加入批次等問題。
- 核心水量平衡公式未改動；自動化測試與 GitHub Actions 已建立。
- 使用者已以無痕視窗完成最終人工驗收。
- 目前的「記憶」只涵蓋同一 Streamlit 工作階段；JSON 可手動帶到其他裝置，但不會自動同步或載入。

## 1. 改版目的

目前系統一次只能設定並演算一種入流情境。辦理水利署例行旬推估時，承辦人通常需要：

- 在推估近期若干旬使用自行研判的共同入流。
- 後續分成氣候上限、氣候下限、專業評估等多種入流情境。
- 在相同出流條件下比較不同入流假設的庫容結果。
- 必要時只計算長官指定的一種情境，或自行增加至4～5種以上。
- 保留不同出流、抗旱措施或操作條件之間的跨批次比較能力。

V2的核心不是固定三情境，而是：

> 一次推估批次包含共用基礎條件、共用出流，以及1～N個可命名的入流情境。

## 2. 實際業務流程

典型例行作業約每旬一次。以8月13日接獲通知、推估期間約8月11日至11月1日為例：

1. 設定展示區間、推估起點、目標日期及起始實際庫容。
2. 近期通常前兩旬由承辦人各旬研判一個入流值，所有情境共用。
3. 後續常見三種情境：
   - A. 氣候上限值。
   - B. 氣候下限值。
   - C. 專業評估，通常採固定Q90，特殊情況可改用其他超越機率或手動數值。
4. 水利署提供的上、下限資料是「旬平均萬噸／日」。承辦人從來源Excel複製所需數值貼入，不要求系統解析整份Excel。
5. 各情境共用同一套出流條件，以隔離入流差異並進行公平比較。
6. 出流通常沿用上次正式推估；上次沒有涵蓋的新旬先採前一年度資料，再由承辦人調整。
7. 抗旱期可針對日期區間或逐日調整出流，底層仍維持逐日演算。
8. 成果須能快速產出旬末庫容橫表，以貼回水利署或內部既有Excel產品。

## 3. 名詞與資料層級

### 3.1 推估批次（batch）

一次完整的推估工作，包含：

- 批次識別碼與顯示名稱。
- 展示起始日、推估起始日、推估結束日。
- 起始庫容與歷史展示庫容。
- 水庫操作參數。
- 共用旬數。
- 1～N個入流情境。
- 一套共用出流。
- 日期／抗旱覆寫。
- 各情境演算結果與成果摘要。

### 3.2 入流情境（scenario）

同一批次中的每個入流情境包含：

- 唯一識別碼，不以顯示名稱作為主鍵。
- 顯示名稱。
- 排序。
- 各年月旬的標準化入流值，演算單位為cms。
- 輸入來源與原始單位。
- 備註。
- 演算狀態與結果。

情境數量為1～N，不寫死A／B／C，也不設定三個為上限。

### 3.3 共用條件

同一批次內所有入流情境必須共用：

- 日期區間。
- 起始庫容與歷史展示資料。
- 上、下灌區需求。
- 公共給水。
- 生態流量與引水上限等水庫參數。
- 日期／抗旱覆寫。

如果需要比較不同出流或不同操作條件，應建立另一個推估批次，再於步驟五跨批次比較，不在同一批次內替不同入流情境配置不同出流。

## 4. 步驟二：多情境入流工作區

### 4.1 基本原則

原有「內建情境／手動批次匯入／混合模式」不再作為互斥的最終資料狀態。新版應有一份可直接確認與編輯的「本次入流工作區」；原有能力改成填入或覆蓋工作區的工具。

可提供快速建立入口：

- 單一情境。
- 水利署標準三情境。
- 沿用目前工作區。
- 空白自訂情境組。

建立後可：

- 新增情境。
- 複製情境。
- 重新命名。
- 刪除情境，但至少保留一個。
- 調整顯示順序。

「水利署標準三情境」只是一個快速範本，自動建立：

- A. 氣候上限值。
- B. 氣候下限值。
- C. 專業評估。

### 4.2 共用旬數

- 共用旬數允許0旬至全部推估旬。
- 例行推估預設2旬，但不可寫死。
- 共用旬必須從推估起點起連續計算。
- 設為0旬時，不顯示共用入流區；所有情境從第一旬獨立輸入。
- 設為全部共用時，只需填一套入流。
- 第一版不支援不連續共用；特殊案件可設為0旬後分別填入相同數值。
- 共用旬數變更時，不可靜默丟棄既有值；需要保留可對應資料，或在會造成覆蓋時先明確提示。

### 4.3 共用入流區

共用期間每旬只填一個值，演算時自動套用到所有情境。每列至少顯示：

- 年、月、旬別或清楚日期範圍。
- 輸入值。
- 單位。
- 換算後cms。
- 資料來源／備註。

### 4.4 情境分歧區

共用期結束後，每個情境分別具有完整旬序列。每個情境可使用：

- 套用單一Q5～Q95至所選旬。
- 從Excel複製貼上多旬數值。
- 直接逐格輸入或修改。
- 複製另一情境後再局部修改。

專業評估通常使用Q90，但Q90只可作範本預設，不可成為不可修改的規則。

### 4.5 單位與貼上

水利署提供數值為旬平均萬噸／日，換算公式為：

```text
入流（cms） = 旬平均水量（萬噸／日） ÷ 8.64
```

貼上工具至少支援：

- 旬平均萬噸／日，套用時除以8.64。
- cms，直接套用。
- 空白、Tab、換行分隔的橫向或縱向數值。
- 數字中的千分位逗號。

套用前必須：

- 顯示預期筆數與實際解析筆數。
- 檢查所有值為非負有限數值。
- 依當前旬別順序顯示配對預覽。
- 筆數不符時不得局部靜默套用。
- 明確顯示原始單位與換算後cms，避免使用者重複換算。

### 4.6 完整性與來源標示

每一個最終入流格應能辨識來源，例如：

- 共用研判。
- 水利署上限貼入。
- 水利署下限貼入。
- 內建Q90。
- 手動修改。
- 複製自其他情境。

未填資料應顯示待填，不可用0、Q50或其他數值無提示補入。任何情境有缺值時，不允許該情境正式演算，並列出情境及缺值旬別。

## 5. 步驟三：共用出流工作區

### 5.1 基本原則

同一批次的所有入流情境共用一套出流。工作區每旬包含：

- 上灌區需求（cms）。
- 下灌區需求（cms）。
- 公共給水（萬噸／日）。
- 初始來源。
- 是否人工修改。
- 備註。

原有能力保留，但改成填入工具：

- 套用前一年度資料。
- 從Excel複製貼上。
- 逐旬直接編輯。
- 日期／抗旱覆寫。

### 5.2 未來永久化後的初始化優先順序

第二階段串接正式共用資料後，初始化優先順序為：

1. 年度預設資料。
2. 上次正式推估中相同「年月＋旬別」的數值。
3. 本次人工修改。
4. 日期／抗旱覆寫。

越後面的優先級越高。

目前第一階段沒有永久的「上次正式推估」，不得假裝已可跨工作階段自動沿用。第一階段可提供整批設定檔的下載／載入，作為過渡及測試工具。

### 5.3 日期／抗旱覆寫

- 僅出流需要日期層級覆寫，入流維持旬尺度。
- 保留現有日期起迄、三項需求及原因備註。
- 底層持續以逐日資料演算。
- 兩筆覆寫若日期重疊，必須警告並阻止演算，或要求使用者先消除衝突；不可依列表順序靜默覆蓋。
- 旬摘要應以實際日數加權，並標示該旬部分或全部遭覆寫。

## 6. 步驟四：批次演算與單一情境詳情

### 6.1 演算原則

- 一次按鈕演算當前批次全部有效情境。
- 每個情境呼叫同一套鯉魚潭逐日演算核心。
- 本階段不修改士林堰引水、灌溉優先、生態流量、庫容上限等核心公式。
- 每個情境必須產生與目前 `df_sim_results` 相容的逐日結果欄位，避免破壞既有成果產品。
- 某一情境失敗時，其他成功結果可保留及查看；批次摘要須清楚標示失敗原因。
- 任何輸入改變後，舊結果必須標示已過期或清除，不得讓使用者誤以為是目前設定的結果。

### 6.2 批次摘要

演算後先顯示一張精簡摘要，每個情境一列，至少包含：

- 情境名稱。
- 演算狀態。
- 期末庫容。
- 最低庫容。
- 累積溢流量。
- 農業削減總水量。
- 空庫天數。

空庫、缺值、演算失敗或其他異常應醒目標示。

### 6.3 詳細成果

摘要下方一次只顯示一個選定情境的完整資料：

- 四張成果指標卡。
- 單一情境庫容歷線。
- 橫向旬推估資訊表。
- 直向旬推估資訊表。
- 逐日明細。
- 各項CSV下載。

切換情境時更換詳細內容，不同時展開多套大型表格及圖表。

預設情境：

- 有「C. 專業評估」時優先選取。
- 否則選取第一個成功情境。
- 只有一個情境時可省略情境選擇器，維持接近現行體驗。

多情境疊圖不放在步驟四，集中由步驟五處理。

## 7. 步驟五：成果產品與跨批次比較

### 7.1 必須保留的既有能力

- 自由勾選單一或多個情境。
- 旬末庫容橫表。
- 多情境庫容歷線圖。
- CSV下載。
- 比較4～5種以上情境。
- 比較不同出流、抗旱措施或操作參數所形成的不同批次。

### 7.2 新版銜接

步驟四完成後應可：

- 一鍵將全部成功情境加入比較區。
- 個別加入指定情境。
- 避免相同結果因重複點擊而建立無法辨識的重複項目。

第五步驟只接收「標準化後的獨立情境結果」，不需要理解共用旬、原始單位、Q90或貼上方式。這是避免步驟二改動連帶破壞產品層的技術邊界。

### 7.3 比較項目與命名

比較項目需帶有：

- 唯一結果識別碼。
- 所屬批次識別碼與批次名稱。
- 情境識別碼與情境名稱。
- 建立時間。
- 逐日結果。
- 完整設定快照或可追溯設定。
- 輸入資料版本欄位，第一階段可先為內建版本或未設定。

顯示名稱建議組合：

```text
2026/08/13 例行推估｜C. 專業評估
2026/08/13 減供測試｜C. 專業評估
```

使用者仍可調整顯示名稱。內部不可只用名稱作為唯一主鍵。

## 8. 設定檔下載／載入

第一階段尚無共用永久資料源，應提供一個可攜的批次設定檔，至少保存：

- 格式版本。
- 批次名稱。
- 日期區間。
- 起始庫容與歷史庫容。
- 水庫參數。
- 共用旬數。
- 所有情境名稱、排序、旬入流及來源。
- 共用出流。
- 日期／抗旱覆寫。
- 建立時間與備註。

建議使用JSON作為系統交換格式。載入時必須：

- 驗證格式版本及必要欄位。
- 驗證日期、旬別、數值及情境數量。
- 先顯示摘要，再由使用者確認覆蓋目前工作區。
- 不載入或執行檔案中的任何程式內容。
- 不將舊演算結果視為目前有效結果，應以載入設定重新演算。

此功能是第一階段過渡方案，不等同正式共用記憶。

## 9. 第二階段：本機 Streamlit＋內網共享資料夾永久保存

第一階段已完成驗收；本節所列功能尚未實作，應另開後續 PR，不與第一階段混在一起。

歷史上曾評估以 Google Sheet 保存共用正式資料，現已由「每台公司電腦本機執行 Streamlit＋公司內網共享資料夾保存正式資料」取代。Google Sheet 不再是第二階段主要永久儲存方案。正式資料夾結構、檔案 schema、append-only、Windows／SMB 寫入鎖、revision 衝突、中斷復原、保存期限與分階段驗收，以 [本機 Streamlit＋內網共享資料夾永久保存規格](LOCAL_SHARED_STORAGE_SPEC.md) 為準。

目標：

- 每個水庫只有一份共用的「目前正式推估批次」。
- 重開網站、換電腦或換承辦人時載入同一基準。
- 以實際年月＋旬別對應重疊資料，不以列號平移。
- 新增出流旬由目前啟用的年度資料補入。
- 新增的氣候上、下限與共用研判入流維持待填。
- 只有明確標示為 Q90 延長預設規則的情境，新旬才可自動套用 Q90。
- 儲存完整批次設定、成果摘要、完整逐日結果、建立人、時間、備註、年度資料版本、程式版本、上一正式版本與 checksum。
- 正式推估及年度資料均新增版本、不覆蓋或刪除舊版；目前啟用版本另以 revision 指標切換。
- 能存取內網共享資料夾者都可試算；儲存正式推估時須填操作人、備註並再次確認。
- 第一版不另設管理密碼；操作人為人工填報，不代表登入驗證。
- `U:` 無法讀取時須明確顯示錯誤，可由使用者選擇內建資料進行非正式試算，但禁止正式保存與年度資料更新。
- 一般使用者最後由桌面捷徑啟動，不要求操作 PowerShell 或 Git。

## 10. 第一階段技術邊界

### 必須做到

- 1～N個入流情境。
- 共用旬數0～全部，預設2旬。
- 萬噸／日與cms貼入。
- Q5～Q95套用。
- 共用出流及日期覆寫。
- 一次批次演算。
- 步驟四摘要＋單一情境詳情。
- 步驟五既有產品相容及批次加入。
- 批次設定JSON下載／載入。
- 相同單一情境輸入下，新舊結果一致。

### 不在本階段

- 任何共用永久資料源；Google Sheet 為第一階段文件當時的候選，現行後續方向改為公司內網共享資料夾。
- 管理密碼或使用者登入。
- 自動載入上次正式推估。
- 年度資料永久化。
- 德基系統修改。
- 修改核心水量平衡公式。
- 不連續共用旬。
- 入流逐日覆寫。


日期與旬別的內部識別應包含年份，避免跨年度錯配。

## 12. 自動驗證要求

至少為下列純邏輯建立可重複測試；即使暫不導入完整測試框架，也應把核心邏輯抽成可測函式：

- 旬平均萬噸／日除以8.64的換算。
- 貼上數值解析與筆數檢查。
- 共用0旬、2旬及全部共用的展開。
- 新增、複製、刪除情境後資料完整性。
- 情境入流缺值驗證。
- 日期覆寫重疊檢查。
- 單一情境新舊演算結果一致。
- 多情境各自使用正確入流，共用相同出流。
- 步驟四選擇情境只改顯示，不改演算結果。
- 加入步驟五後結果及設定快照未遺失。
- 設定JSON round-trip：下載後載入能恢復等價設定。
- 改動輸入後舊結果不再被視為有效。

## 13. 人工驗收清單

### A. 單一情境

1. 建立單一情境並設共用0旬。
2. 以現行版本相同日期、起始庫容、入流及出流演算。
3. 核對逐日庫容、旬末庫容、溢流及農業削減結果與舊版一致。
4. 確認只有一個情境時步驟四不顯得冗長。
5. 加入步驟五並下載原有產品。

### B. 標準三情境

1. 使用標準三情境範本。
2. 設共用2旬，確認前兩旬只需輸入一次。
3. 將水利署旬平均萬噸／日貼入A與B，核對cms換算。
4. C套用Q90後局部修改一旬。
5. 執行全部情境，核對前三個情境共用期結果一致，分歧後結果不同。
6. 步驟四摘要同時顯示三列，但完整表格一次只顯示所選情境。
7. 步驟五可同時產生A、B、C旬末庫容列及疊圖。

### C. 0旬與多情境

1. 建立5個情境，共用0旬。
2. 從第一旬分別貼入不同數值。
3. 執行後切換查看5個情境詳情。
4. 自由選擇其中1個、3個或5個加入步驟五比較。

### D. 全部共用與不同操作方案

1. 建立多個情境並設全部共用，確認只需一套入流。
2. 完成本批次演算。
3. 修改共用出流或抗旱覆寫，另建新的比較批次。
4. 確認步驟五可跨批次比較不同操作方案。

### E. 出流與抗旱覆寫

1. 套用前一年度出流後逐旬修改。
2. 建立不重疊的日期覆寫，核對旬加權摘要及逐日結果。
3. 建立重疊覆寫，確認系統警告且不默默採用其中一筆。

### F. 設定檔

1. 下載包含多情境、共用旬及覆寫的JSON設定。
2. 清空或重開工作區後載入。
3. 確認所有設定恢復但必須重新演算。
4. 載入格式錯誤或缺欄檔案，確認不覆蓋目前工作區。
